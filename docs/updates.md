# In-app updates

WhisperDrop 2.6.0 includes Sparkle 2.10.0; the published release is build 11. Use **WhisperDrop 2 > Check for Updates…**, or the same button in **Settings > General > App updates**. Automatic daily checks are optional and off by default. Updates are installed only after confirmation. System profiling and automatic installation are disabled.

The updater replaces the app bundle. Models, library files, preferences and saved text versions remain outside it. It waits for recording, dictation, transcription, imports, file moves, model downloads, writing actions and queued note summaries to finish. Close a transient writing review panel before updating. The main writing draft and suggestion are saved atomically before restart, restored on launch, and never restore a cross-app replacement target. If saving fails, the restart waits and Settings offers **Retry update**.

## Release configuration

`Resources/UpdateConfiguration.json` contains the public Ed25519 key and the production feed URL:

`https://github.com/Zer0codestuff/whisperdrop-2/releases/latest/download/appcast.xml`

The private key was generated with Sparkle's official tool and is stored in the login Keychain under account `io.github.zer0codestuff.whisperdrop2.sparkle`. It is not in the repository or app bundle. Both the update archive and feed must be signed with this key. The client verifies the archive before extraction and rejects unsigned or changed feeds without a timed fallback. Production feeds require HTTPS. Loopback HTTP is accepted only by the separate verification bundle identifier.

The production feed is published with the 2.6.0 GitHub release (October 6, 2026), which carries the signed `appcast.xml` and its ZIP. Versions before 2.6.0 have no updater and need one manual replacement with the DMG. Later versions update from the app.

## Prepare a release

After building and validating the app:

```sh
scripts/prepare-updater.sh
scripts/package-update.sh
```

The preparation script downloads Sparkle's pinned official tools and verifies the release archive SHA-256. Packaging preserves framework symlinks, checks the embedded public key against the Keychain key, signs the update and feed, and prepares files under `dist/update-VERSION-buildBUILD/`. It does not upload anything. Keep `CFBundleVersion` increasing even if the displayed version is unchanged.

After the user approves publication, attach the ZIP and `appcast.xml` to the matching GitHub release. The ZIP name and release tag must match the URLs generated by the script. Each new latest release needs its own signed feed. Do not edit a signed feed or its embedded release notes after generation; regenerate and sign it instead. Publish only release artifacts and public configuration, never test data, model weights or the private key.

## What the owner needs to do

No paid Apple Developer account or separate update server is needed for this implementation. The owner approves the first public release and keeps a secure backup of the signing key. macOS may ask permission for Sparkle's signing tools to access that key.

To export a backup, use the official tool with `--account io.github.zer0codestuff.whisperdrop2.sparkle -x /path/to/secure-backup-file`. The exported file contains a private signing credential. Store it in an encrypted backup or password manager, outside Git. No private-key export was made during this work. Losing the key while distributing ad hoc signed builds can require another manual bootstrap with a new key. Preserve the current key instead of regenerating it for each release.

Apple Developer ID and notarization remain separate from Sparkle's signatures. The app is still ad hoc signed and unnotarized. This updater does not remove Gatekeeper warnings or guarantee that macOS keeps Accessibility and Input Monitoring grants after an update.

## Verification

On the M1 MacBook Air with 8 GB RAM, a native isolated app updated from build 10 to build 11 through **Check for Updates**, **Install Update**, and **Install and Relaunch**. Sparkle downloaded a signed ZIP from a loopback server and verified a signed feed. The app reopened at build 11. Strict nested signatures passed; canonical synthetic history, writing draft, suggestion and downloaded model hardlink inodes were preserved. The note and draft were inspected in the native UI. No Apple Developer membership, administrator authorization, privacy grant or security bypass was used.

Two negative native checks kept build 11 installed: a changed ZIP with its original signature was rejected as improperly signed; a changed signed feed was rejected before offering an update. The valid unchanged feed then reported that build 11 was up to date. The automatic-check switch was verified on and off. A status bug that labelled the no-update result as an error was fixed and covered by a regression test.

The final full release suite discovered 145 tests: 135 passed, ten optional fixture-dependent checks skipped, zero failures. New checks cover active-operation restart guards, delayed restart, failed draft save and retry, main-draft preservation during a transient panel, restart restoration, unreadable-draft backup, and normal no-update/cancellation statuses. Earlier writing-model and speech validation remains documented in `writing-tools.md`.

The build 10 DMG was mounted read-only: 120 regular files and nine framework links matched the candidate, and all 14 Mach-O executables passed strict signature checks. Both Turbo and the rebuilt Parakeet runtime silently transcribed the same 12-second Italian fixture successfully. Packaging now checks the DMG checksum before reporting success; a partial image created during low disk space was rejected and rebuilt. The ZIP also passed its compressed-data integrity check.

On October 3, the production build 10 replaced build 9 in `/Applications/WhisperDrop 2.app`. The signed production feed and ZIP passed independent signature and SHA-256 checks. The installed bundle matched the candidate, launched successfully, and exposed Check for Updates in Settings, General. Every retained data file was checked before and after launch; canonical history, saved-file references and model hashes/inodes were unchanged. The previous app bundle was removed. The feed was not public yet at that point.

The end-to-end update used an isolated writable installation and local HTTP transport, with the same Ed25519 validation required in production. It does not establish behaviour for a quarantined first download, a root-owned installation needing authorization, macOS 14 hardware, or the public GitHub feed, which was published later. No active microphone session was used; restart deferral was exercised through the controller tests. Reports and synthetic fixtures are in ignored `.experiments/updater/`.

Reference: [Sparkle setup](https://sparkle-project.org/documentation/), [publishing](https://sparkle-project.org/documentation/publishing/) and [security settings](https://sparkle-project.org/documentation/customization/).
